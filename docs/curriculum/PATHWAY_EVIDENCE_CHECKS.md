# Pathway structure and evidence checks

Status: authoring pilot, 9 November 2026. No human reviewers are currently part of the workflow. These checks help the author and AI tutor team find omissions; they do not certify a curriculum or grant student mastery.

`data/curriculum/pathway-evidence-pilot.json` records one JavaScript Arrays unit using a reusable structure: capabilities, ordered unit prerequisites, existing path prerequisites, trace/use/choose/transfer assessment pointers, an application, and triggered recovery activities. It is intentionally a **draft**. Python and Java can use the same fields once their own units and assessments are authored; their topic order and native constructs should be chosen independently.

Run `python tools/check_pathway_evidence.py` or `pytest tests/test_pathway_evidence.py`. The checker verifies IDs, language ownership, prerequisite order, existing quiz and Explain links, assessment role, distinct evidence families, and that an application uses only declared or previously taught capabilities. It reports independent-assessment gaps separately from broken links. The current pilot has two gaps: its choice and transfer tasks are guided, ungraded activities. A quiz pointer means an assessment exists; it does not mean any student has passed it.

Before adding another unit, fill its capability and prerequisites, identify a focused trace and use check, then author an independent choice and transfer task in distinct problem families. Link a small application to capabilities taught so far and name a recovery activity for a specific observed difficulty. Add tests for ordinary, boundary, and misleading cases. After structural checks pass, examine the actual lesson and answer key, reproduce code examples, try representative correct and incorrect submissions, and run a learner walkthrough. Record unresolved teaching uncertainty. Do not turn `evidence_links_complete` into a publication or mastery flag; it says only that the declared links and assessment categories are present.
